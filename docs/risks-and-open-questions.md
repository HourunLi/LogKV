## 8. 风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| **key 空间未必是语义空间**（§2.5，最根本）| 对句法头/位置头，前提不成立 | per-head 聚类下自动退化为 no-op；Stage 0 必须逐层逐头统计 |
| **`(g_max, ℓ_block)` 选错** | 要么跨度失控，要么语义分组白做 | S0.0 是最高优先级实验 |
| **`λ_rel` 敏感** | needle 并入大簇，机制失效 | S0.3 提前证伪；进主扫描 |
| **按 key 聚类不保证 value 同质**（§11-D）| 分数侧准了但读出侧仍 smear，收益打对折 | S0.4 必须同时测 value 方差 |
| **早期路由错误不可恢复**（§5.6）| 只合并从不分裂，冷启动的错误永久留存 | `γ` 遗忘因子缓解 centroid 漂移；冷启动方案待定（§13-F）|
| **锚点展开撑爆读出槽池** | 计算量和峰值内存超基线 | S0.6 先测；缓解见 §4 |
| **mass bias 未按 M 摊薄**（静默 bug）| 大跨度簇权重被放大 M 倍 | §5.14 的守恒单测是硬性 gate |
| **相邻更正仍被均值池化**（§2.4）| supersession 只解决了远距离那一半 | 已知边界；唯一覆盖路径是 Γ 的 delta-rule 广义化 |
| **内存不对齐比较** | 论文被质疑"只是多用了内存" | 见 §4，从第一个实验起报告两笔账 |
| **训练期显存随内容波动** | batch 内簇占用不同 | 预分配上界固定，训练期必须开硬顶 |


## 11. 技术难点清单（动手写代码前必读）

按"会不会挡住你"排序。**A、B 必须在写第一行代码之前把方案定死。**

### A. 训练侧重放确定性——语义路由打破了它赖以成立的前提（最危险）

`LogKVStreamTrainingAttention` 的 backward **不保存图，而是重置 cache 并重放整条流**。
正确性论证明确写在 docstring 里：

> "The replay is deterministic: compaction is pure mean-pooling with **count-based
> binary carries** — no RNG, identical shapes take identical kernels"

现有 cache 结构**只依赖计数，完全不依赖数据**，所以重放必然重建逐位相同的状态。
语义路由恰恰把结构变成数据依赖：一次 `argmin` 平局、一次距离落在 `λ_new` 边界上的
浮点末位差异（TF32、einsum 归约顺序、autograd 开启与否导致的 kernel 选择不同），
就会让某个 token 进了另一个簇——**而一个路由决策的分歧会沿整条流放大，最终梯度属于
一个和 forward 输出不同的函数**。不会报错，只会让 loss 曲线莫名其妙。

**修法（硬性要求）**：forward 时把路由决策写进 `op_log`（**是操作日志不是 token→cluster
映射**——Ward 合并会复用 cluster id，只记归属无法重建结构，见 §5.21-2），backward
**重放这个操作序列而不是重算**。`O(T)` 整数，可忽略。把"靠浮点可复现"换成"构造上精确"。
注意 §5.19-5 的时序冲突。

### B. 路由的顺序依赖——wall-clock 会直接爆炸

`_flush_pairs` 存在的**唯一理由**就是把逐对串行的 flush 批量化。语义路由等于把刚被
消除的串行依赖请回来：32k / 2 = 16k 次 flush × 28 层 = **单次前向 45 万次 Python
迭代**，光 kernel launch 开销就是几十秒量级。

**修法**：§5.4 的三阶段批量化，Phase 2 的总次数被 `E[K]` 界住而非 `O(T)`。
**代价是一个近似，必须由 S0.8 验证。**

### C. `SEG_max` 曾把预分配乘爆（已在 §5.11/§5.12 修掉，记录以免复发）

v3.1 早期版本把预分配写成 `K_max × SEG_max × L_max × B′ × M_max` ≈ **4 万槽**，比
vanilla 大一个数量级。根因是误以为每个 segment 需要自己的 ladder。**正解**：每
cluster 只有一条 ladder，segment 只约束合并；且 `L_alloc` 按均衡界而非"单簇独吞"
定尺（§5.12）。同时记住 §4 那两笔账要分开。

### D. 按 key 聚类只同质化了分数侧，没同质化读出侧（可能砍掉一半收益）

聚类的是 `k`，但 attention 返回的是 `v̄`。**key 相似不蕴含 value 相似**——"分数是 X"
这个 key 模式下，value 可以是 100 也可以是 90。于是分数侧 ✓、读出侧 ✗。典型症状是
"niah 分数上去了但答案文本是错的"。**S0.4 必须同时测 key 方差和 value 方差**。
若 value 方差居高不下，可选项是按 `[k; v]` 联合聚类（会伤路由质量）或簇内按 v
二次分裂。

### E. flush 时机若依赖 chunk 边界 → 静默的训推不一致

路由顺序由 flush 调度决定。若 flush 只由窗口占用触发（与 chunk 无关），调度就是
token 索引的确定函数；但只要有任何一处依赖 chunk 边界，`train_block` 不同或 prefill
分块不同就会产生**不同的簇划分**。**必须显式验证，不能假设。**

### F. 冷启动：最初若干 token 定义了整篇文档的簇

DP-means 顺序依赖，而文档开头往往是 system prompt 或样板文字，attention sink 也最先
出现。用它们播种 centroid，等于让最不具代表性的内容决定整篇文档的语义划分。而
§5.6 说过**早期错误不可恢复**。可选缓解：用窗口内已有内容播种；或前若干 token 用更
激进的 centroid 更新率。**尚未定案（§13-F）。**

### G. 压缩函数永远不会被训练——架构性限制，不是 bug

梯度只经由 token 自己所在的 block 到达（cache 提交的是 detached 副本），一旦被压进
槽就再也没有梯度。所以**聚类质量学不出来**，CPT 只能教模型去适应一个固定的启发式
划分。两个后果：`λ_rel`/`g_max` 只能靠扫参不能靠学习；**Stage 0 的离线测量基本就是
最终答案**。这一点应该在论文里主动讲清楚。

### H. `λ·log w` 的标定分布变了（附带一个好消息）

现在同层槽宽度相同，`log w` 只区分距离；语义簇下 `w` 完全由内容决定，分布高度偏斜。
`λ` 是隐含地按旧分布 CPT 出来的。

**好消息**：mass bias 在"槽内 token 完全相同"时精确、否则一阶——而语义聚类正好在
最小化这个误差项（Jensen 间隙随簇内同质性收缩）。所以 **bias 的精度实际上是提升的**。

### I. 逐层差异

早期层的 key 接近 token embedding 加位置，几乎没有主题结构。§2.5 的"逐头报告"应扩展
成**逐层 × 逐头**。很可能的结果是这套方法在中层语义头上有效、在浅层和位置头上是
no-op——这决定了是否该做成"只对部分层/头启用"。

## 12. 未决问题清单（还没讨论清楚的）

按"会不会影响结论"排序。这些**不是**已知风险（那些在 §8/§11），而是**尚未形成方案**
的空白。

### A. decode 阶段完全没讨论

所有设计都围绕 prompt 的 prefill，但 **niah 和 LongBench 都是生成式评测**。生成的
token 同样会滑出 recent window 并被路由，于是：生成内容会**消耗 cluster 预算**、和
prompt 抢 `K_max`；长推理链可能占掉大半个簇池；生成 token 语义紧扣答案，可能反复
触发新簇。**至少要决定：生成 token 是否参与聚类、是否共享同一个 `K_max`、还是单独
留一块预算。**

### B. `s_h` 的估计方式（§5.2 里手挥过去了）

在线估计 vs 离线标定的选择没做。在线估计让阈值随序列演化，引入 §11-E 的变体风险；
离线标定更安全但需要一个标定 pass。**而 `λ_rel · s_h` 是全方案最敏感的量。**

### C. attention sink 会永久占掉簇预算

sink 自成一簇是"feature"，但 `K_max=16` 时 1~2 个槽被 sink 永久占住就是 6~12% 的
预算，而 sink 携带的信息量近乎为零。是否该给 sink 一条单独通路（不占 `K_max` 的
固定精确槽）？这在形式上很像 pin（失败过），但 sink 与 pin 有本质区别（结构性、
位置固定，不是按内容挑选）。**权衡没做。**

### D. `K_max` 与 multi-needle 的相互作用

8 个 needle 各自成簇要 8 个槽，占 `K_max=16` 的一半，加上 sink 只剩 6~7 个给
haystack。而 multi-needle 恰恰是文档指定的"真正拉开差距"的实验。**`K_max` 的定尺
现在只由 `K_eff` 决定，没把 needle 数考虑进去。**

### E. Stage 2 的 Config A 闸门不可证伪

`K_max=1` 被定为硬性正确性闸门，但它和现有方案有两处**故意的**差别（锚点 vs
post-RoPE 均值、level 0 存单 token vs token 对），所以本来就不该复现 0.1716/0.0827，
只会"接近"。**没有容差定义的闸门等于没有闸门。** 要么定明确的容差带，要么改成对照
一个"同 ladder 形状的现有方案重实现"，让差异只剩位置表示这一项。

### F. 冷启动方案（§11-F 的对策部分）

已知问题，但缓解方案（窗口播种 vs 激进更新率）没有选定，也没有评估标准。

### G. 缺少 eval-time 的机制探针

Stage 0 全是离线 dump 分析。若 Stage 2 表现不好，**无法归因**是聚类差、位置表示差、
CPT 分布漂移、还是实现 bug。另一分支有 D1 自检那种在线诊断，这边对应的应该是"运行时
记录 needle 实际落在多大的簇里"。**探针没设计。**

### H. 两个轻量但值得记的

- **跨层独立聚类**：同一 token 在第 5 层属于簇 3、第 20 层属于簇 7。机制上没问题，
  但意味着**不存在贯穿模型的"语义段"概念**，论文讲故事时不要暗示有。也留了一个未
  探索的优化空间（跨层共享聚类以省路由开销）。
- **模型怎么理解"同一份内容出现在两个位置"**：锚点展开让一个 entry 在读出侧看起来
  像"两个内容完全相同、位置不同的 token"。模型会读成合理的摘要还是困惑的信号？
  **先验上不知道**，数学正确不保证模型接受，只能等 Stage 2。

## 13. 压缩机制本身的剩余空间（未探索）

这一节讨论的是**槽内怎么压**这条轴上还没被动过的地方，与 §2/§5 讨论的"谁和谁同槽"
正交。按"回报 ÷ 成本"排序，前两条都能在 Stage 0 用同一批 dump 顺带测掉。

### 13.1 窗口 / ladder 的预算重分（零实现成本，可能是最大杠杆）

按 §5.6 的定尺，32k 下 `recent 1024 + entry 1320 = 2344`，**窗口占 44%，而且是唯一
一块零压缩的区域**。

关键在于：**新设计里 level 0 存单 token，它和窗口里的 token 是同一种东西**——都是
精确的 k、精确的位置。窗口相对 ladder 的唯一优势不是"更精确"，而是"不会被将来的
合并波及"。于是这变成一个明确的取舍：

| 花在哪 | 保证什么 |
|---|---|
| recent window | **最近的 1024 个 token** 精确 |
| 各簇的 level 0 | **每个簇最近的 `B′` 个成员**精确 —— 与位置无关 |

**对捞针而言后者严格占优**（needle 通常不在最近 1024 里，但它在自己的簇里永远是最新
成员之一）；对通用语言建模而言前者更重要（局部连贯性）。

而 `recent_size = 1024` 是从**位置分桶时代**继承下来的——那时根本不存在"语义精确"
这个选项，窗口是唯一能保证精确的地方。**新设计下这个比例没有理由不变。** 提高 `B′`
还直接抬高 §5.9 的无损阈值，所以应该把 **`recent_size : K_max : B′` 当作一个三方
分配整体扫**，而不是只扫 `K:B′`。

### 13.2 分辨率的分配曲线 `B′_ℓ`（纯离线可测，可独立成文）

Fenwick 现在给每层**固定 `B′` 个 entry**，翻译成资源分配就是"每个倍程分到的槽数是
常数"。**这条沿 ladder 层级的分配曲线从来没有被论证过，它只是二进制计数器的副产品。**

> **新颖性主张要让一步**：CompressKV（§9）的**层间**预算分配（按压缩前后 attention
> 输出的 Frobenius 误差按比例分配）在方法论上就是同一件事——测量驱动的率失真分配。
> 所以这里能主张的是**分配轴不同**（ladder 层级 vs 模型层），不是"没人做过测量驱动的
> 预算分配"。写论文时引它作为跨层版本的先例。 正确的提法是一个
率失真分配问题：

```
给定 Σ_ℓ B′_ℓ ，选 {B′_ℓ} 最小化  Σ_ℓ (该倍程被 query 命中的概率) × (该倍程的池化失真)
```

两个因子都可测：命中概率就是稠密前向里**注意力质量随距离的分布**，失真就是槽内方差。
真实 LLM 的注意力对距离高度非均匀（强 recency bias + attention sink），所以最优的
`{B′_ℓ}` 几乎肯定不是常数。

实现上只是把 `B′` 从标量变成每层的数组，进位条件跟着变，**不动任何数学**。在语义簇
版本里同样成立，只是"距离"变成"簇内年龄"。**Log-Linear Attention 那条线的分桶也是
固定按 2 的幂，同样没人问过分配曲线**，所以这可以是一个独立的贡献点。

### 13.3 Σ 与 Γ 的非对称秩分配

现在打分侧和读出侧各给一个 rank-1，但两者的误差性质不对等：

- **分数误差部分自我纠正**——softmax 是个排序，小扰动只是稍微改变权重；
- **读出误差直接进入输出**，而且 §11-D 说了按 key 聚类不保证 value 同质。

所以 **Γ 应该拿到比 Σ 更多的秩，而不是平分**。

**这里有个和聚类的替代关系值得注意**：语义聚类让簇内内容同质 → Σ 的协方差谱更集中
→ **rank-1 对 Σ 可能变得足够用**，省下的秩预算应转给 Γ。也就是说"提高秩"和"改善
成员划分"是攻击同一个误差项的**替代品而非互补品**。S0.4 测簇内协方差**谱**（不只是
方差标量）就能判断该往哪投。

实现代价不大：`_dominant_eigvec_small` 那套小矩阵幂迭代本来就是为提取主特征向量写的，
推广到 rank-2 是同一套机制多跑一轮。文献上 [KVSlimmer](https://arxiv.org/pdf/2603.00907)
做的正是 K/V 非对称合并的理论分析，可引。

### 13.4 几条更小或更远的

- **合并顺序（Fenwick 固定配对 vs 贪心最小代价）**：已登记为 S0.2 决定的分叉点
  （§5.11），不重复。
- **b 叉进位**（一次合并 b 个而非 2 个）：`L = log_b(n/B′)`，层数少了但每次合并损失
  更大。**b=2 已是给定 `B′` 下分辨率最细的选择**，所以这是个省内存的旋钮，不是改进。
- **量化**：槽现在是 bf16/fp32，完全没量化，正交的 2~4×。低新颖度，但有一个值得测的
  小观察——**池化后的槽应该比原始 token 更好量化**，因为均值压掉了动态范围和离群值，
  而离群值正是 KV 量化的老大难。"先池化再量化"可能严格优于"先量化再池化"。
- **跨层 / 跨头冗余**：**最大的未开垦轴**（与 token 轴正交可叠加，CLA/YOCO/LCKV 都在
  这条线上），乘数比任何 ladder 精细化都大。但它是另一篇论文，混进来会稀释主线贡献。
